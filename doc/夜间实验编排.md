# 夜间实验编排

## 当前状态：编排器可测试，双构象实验尚未接入

`scripts/run_overnight.py` 是失败即停的顺序执行器，不是自动写模型或自动修 bug
的 agent。`scripts/overnight_dual.json` 中的命令仍为 `null`：双状态模型、可达目标、
二元保持性和过拟合入口尚未实现，因此预检必须拒绝运行。不要用单状态 v2 的 smoke
替换它们，也不要手工填入恒真的验收结果。当前不能启动完整双构象实验。

## 顺序和预算

实现工作在启动脚本之前完成；十小时是机器实验的上限，不包括自动实现模型。

| 阶段 | 最长时间 | 验收内容 |
|---|---:|---|
| contracts | 30 分钟 | 状态隔离、等变性、化学几何、POI 更新、可达监督 |
| binary_preservation | 60 分钟 | 相同初态、求解器和随机数下的二元一致性 |
| overfit | 60 分钟 | 损失与旋转学习、梯度、专家冻结、保存恢复 |
| pilot | 60 分钟 | 留出验证、短轨迹、最终装配、吞吐测速 |
| train | 330 分钟 | 有限训练、checkpoint、验证记录 |
| evaluate_protac | 30 分钟 | 独立进程加载训练权重，报告局部和整体指标 |
| evaluate_mgd | 30 分钟 | 同上，失败样本必须计入分母 |

各阶段提前完成便进入下一步，不为凑足十小时等待。训练入口必须支持主动限时、
定期原子保存 checkpoint，并在 `{seconds}` 内正常结束；超时强杀只用于兜底，
不能当作正常训练结束，也不保证被杀瞬间能够保存。后续评估时间预先留出。

## 命令接入契约

每阶段 `argv` 是无 shell 的参数数组。支持 `{python}`、`{root}`、`{out}`、
`{report}`、`{run_id}`、`{checkpoint}`、`{seconds}` 占位符。`{out}` 已建好；
需要新建输出目录的程序应使用其子目录。禁止后台脱离编排器运行。

阶段收到 `EXPERIMENT_RUN_ID`、`EXPERIMENT_STAGE`、`EXPERIMENT_ARCHITECTURE`、
`EXPERIMENT_REPORT` 环境变量。正常退出之前写 JSON 报告：

```json
{
  "run_id": "本次环境变量中的 ID",
  "architecture": "dual_consensus_experimental",
  "stage": "contracts",
  "passed": true,
  "checks": {
    "state_isolation": true,
    "frame_equivariance": true,
    "chemical_geometry": true,
    "poi_update": true,
    "reachable_target": true
  },
  "artifacts": ["/absolute/path/to/measured_evidence.json"]
}
```

其他阶段必须提供 `run_overnight.STAGES` 列出的全部检查。具体数值阈值和计算由
各科学验收入口实现并测试，编排器只验证报告契约，不能证明报告中的结论正确。
训练报告还需给出非空 checkpoint 的绝对路径；两次评估必须记录相同路径。
禁止在 benchmark 上进行训练、挑选超参数或以 oracle 最佳样本冒充 top-1。

## 运行与检查

```bash
python tests/test_overnight.py
python scripts/run_overnight.py --dry-run
```

第二条目前应返回退出码 2，并列出未实现的阶段。所有入口接入后，在分配到物理
GPU 3 的 SLURM 作业内运行：

```bash
/root/.conda/envs/tricoopdiff/bin/python scripts/run_overnight.py \
  --out /tmp/pymp-f2c2db1a/results/overnight_dual_run01
```

程序按 GPU UUID 限制为物理 GPU 3；分配不匹配时拒绝执行，不能自行使用未分配
的卡。SLURM 时间需要覆盖实验预算及清理时间。无 `--resume` 或跳过门禁选项；
输出目录必须全新，重跑不会覆盖旧结果。检查 `status.json`、`plan.json` 和逐阶段
`.log` / `.json`。异常、SIGTERM 和 Ctrl-C 会终止当前子进程组并记录失败；操作系统
强制 SIGKILL 或断电不保证最终状态落盘。

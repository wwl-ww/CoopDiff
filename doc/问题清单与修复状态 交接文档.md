## 1. 已修复的问题（全部已提交）

> 状态标注：本节所有条目现已全部提交（§1.2/§1.3 = `cacbb7f`；§1.1/§1.4–1.7 = `debug-se3-loss` 合并 `3a90cd1`）。

### 1.1 旋转约定 sign bug（PROTAC rot）— 已修 [已提交]

- **位置**：`tricoopdiff/diffusion.py` 的 `add_noise_protac`（~L188）与 `reverse_step_protac`（~L376）。
- **问题**：TriCoopDiff 施加旋转用 `@ exp([ω]×)`（无转置），而 DiffDock 专家用 `@ exp(-[ω]×)`。专家把 TriCoopDiff 的位姿读成旋转 `-ω`，输出 `score_vec(σ,-ω) = -score_vec(σ,ω)`，与训练目标反号 → `reverse_step` 放大 |ω|。
- **修复**：两处都加 `.transpose(-1, -2)`（`@ Rᵀ = @ exp(-[ω]×)`）。**必须两处一起改**——只改前向会放大而不是去噪。
- **注意**：`add_noise_se3` / `reverse_step_se3` 是 SE3 刚体，用 `@ R` 约定且自洽，**没动**。

### 1.2 问题 #1a：帧不一致（sub2 tr/rot 在 POI 帧）— 已修 [已提交]

- **位置**：`tricoopdiff/model.py` `forward` L193-201。
- **问题**：sub1（E3-L）的 tr/rot 在 E3 帧，sub2（POI-L）在 POI 帧，直接相加是维度错误。
- **修复**：合并前 `r_poi_to_e3 = r_e3.transpose(-1,-2)`，`scores_2['tr_score'] @ r_poi_to_e3`、`scores_2['rot_score'] @ r_poi_to_e3`；`tor` 是内部自由度、帧无关，不动。

### 1.3 问题 #1b：双重计数破坏零-FiLM 透明性 — 已修（= 方案 B）[已提交 + 单元验证]

- **位置**：`tricoopdiff/tribrain.py` `MergeGateHead`（L479）、`tricoopdiff/merging.py` `merge_residual_gated`（L50）、`tricoopdiff/model.py`（L44 `use_learned_merge=True` 默认、L206-211 调用）。
- **问题**：旧默认 `s_q = s_q1 + s_q2` 是两个独立二体力场之和，零-FiLM 时 ≠ 纯 E3-L，导致基线 DockQ 0.153 vs 纯 DiffDock E3-L 0.844。
- **修复**：改为 residual-gate `s_q = s_q1 + g*(s_q2 - s_q1)`。`MergeGateHead` 是 `Linear(node_dim,3)`，**weight 与 bias 都 `zeros_` 初始化** → 无论输入如何 `g≡0` → 零-FiLM 时 `s_q = s_q1` = 纯 E3-L，透明性基线天然成立。数学上等价于文档方案 B 的 `s_q = α·s_q1 + (1-α)·s_q2`（取 `g = 1-α`）。`merge_direct_addition` 保留为 L0 ablation（`use_learned_merge=False` 时才用）。
- **已验证**：GATE1 零-FiLM 透明性 PASS（tr/rot/tor allclose，max_abs_diff=3.8e-06）。

### 1.4 问题 #2：SE3 去噪只修平移、忽略旋转 — 已修 [已提交]

- **位置**：`tricoopdiff/train.py` `_estimate_denoised_se3`（L270）、调用点 `compute_loss`（L190）。
- **问题**：旧实现只对 POI 质心做 Tweedie（`tr_score`），完全丢弃 `se3_score[:, 3:]`（旋转），`denoised_poi` 的方向仍带噪声。
- **修复**：补旋转 Tweedie。SE3 前向 `noisy = (clean-center) @ exp(ω) + center + tr`（无转置），目标 `-ω/σ_rot²`，故 `ω̂ = -σ_rot²·rot_score`，去噪旋转 `@ exp(-ω̂) = @ exp(σ_rot²·rot_score)`（无转置，匹配 SE3 `@ R` 约定）。签名改为 `(noisy_poi, se3_score, sigma_tr, sigma_rot)`。
- **风险**：`loss_phys` 的梯度路径现在同时经过旋转 score，可能改变 Phase-1 物理项量级（预期正确，但 smoke 里若 `loss_phys` 异常需留意）。

### 1.5 问题 #3：PROTAC 前向 λ_q 门控（t≤0.7 时噪声为 0）— 已修 [已提交]

- **位置**：`tricoopdiff/diffusion.py` 的 `add_noise_protac`（tr/rot）与 `add_torsion_noise`（tor）。
- **问题**：`lambda_q = get_lambda_q(t)` 在 t≤0.7 时为 0，PROTAC 前向在这段不加噪声 → score 目标恒 0，训练分布缺失。
- **修复**：删掉 `lambda_q` 门控，PROTAC 用完整 t∈[0,1] 调度（与 SE3 修法一致）。`get_lambda_q` / `lambda_q_threshold` 参数保留为 dead code（未删）。
- **风险**：训练分布变化，已训练 checkpoint 的损失基线不连续。

### 1.6 问题 #4a：checkpoint 冗余（写 ~131MB 冻结专家）— 已修 [已提交]

- **位置**：`tricoopdiff/train.py` `save_checkpoint` / `load_checkpoint`（L329+）。
- **修复**：`save_checkpoint` 不再写 `model_state_dict`，只存 `tribrain_state_dict` + optimizer + scheduler + global_step；`load_checkpoint` 用 `.get()`/`in` 向后兼容旧 checkpoint（缺 optimizer/scheduler key 时只恢复权重和 step）。

### 1.7 问题 #4b：接触距离硬编码 3.4Å — 已修 [已提交]，进一步升级为真实 VDW [已提交 `0e8b1c4`]

- **位置**：`tricoopdiff/train.py` `__init__`（新增 `contact_distance=3.4`）与 `_physical_loss`（L302）。
- **修复（已提交 `debug-se3-loss`）**：硬编码 `3.4` 改为 `self.contact_distance`，默认行为不变。
- **升级（已提交，`0e8b1c4`）**：`_physical_loss` 新增 `ligand_features` 入参，从配体原子序数解码 Bondi VDW 半径（`_ligand_vdw_radii`）；蛋白坐标 Cα 级 → 碳半径 1.7 Å。碰撞项 `F.relu(3.4 - dist)²` → `F.relu((r_i+r_j) - dist)²`。`ligand_features is None` 时回退到单值 `contact_distance`（默认 3.4 Å == C···C Bondi 半径和，故元素感知路径是其严格泛化）。这解决了 code-review **BUG-10**。

## 2. 待调查（新发现，2026-08-17）：零-FiLM 基线采样保真度未达标

**实测**（smoke job 139256 PASS；eval job 139257，32 walkers × 20 steps）：

| 指标 | 旧（双重计数） | 现在（residual-gate） | 目标（纯 DiffDock E3-L） |
|------|------|------|------|
| E3-interface DockQ best | 0.153 | **0.215** | **0.844** |
| PROTAC RMSD best | — | 4.99 Å | ~1–2 Å |
| PROTAC pocket dist best | — | 5.50 Å | ~1–2 Å |
| PROTAC pocket dist **mean** | — | **49.8 Å** | — |

**结论**：

- score-merge 透明性**已修好**（GATE1 证明 `g≡0 → s_q = s_q1`，数值差 3.8e-06）。
- 但 0.215 仍远低于 0.844，且**不是合并造成的**——零-FiLM 下 `s_q` 就是纯 E3-L。真正病灶：**TriCoopDiff 的 E3-L 反向采样循环没有复现 DiffDock 原生 inference**。
- 铁证：`protac_pocket_dist_mean = 49.8 Å`（32 walker 平均离口袋 50 Å、best 才 5.5 Å）、`protac_rmsd_best = 4.99 Å`。若 E3-L score 正确，零-FiLM 下 walker 应落在口袋附近（几 Å），而非 50 Å 外 → PROTAC 基本没被 E3 约束，采样在漂移/发散。

**候选排查点（派 agent 逐项对照 TriCoopDiff 反向循环 vs DiffDock 原生 inference）**：

1. **步数/调度**：eval `steps=20`、`get_inference_schedule` 线性 t=1→0 vs DiffDock 原生 `t_to_sigma` 映射、步数、每步 σ。
2. **旋转约定**：`.transpose(-1,-2)` 修复方向对，但需与 DiffDock `modify_conformer` + inference 逐行核对是否还有第二处约定错（tr/rot/tor 更新顺序、质心处理）。
3. **初始化**：`TernaryInitializer.initialize_protac` 的 t=1 分布 vs DiffDock 原生初始分布。
4. **tor 反向步**：`reverse_step_torsion` 与 DiffDock 的一致性。

**进展（2026-08-17 晚）**：诊断报告《采样保真度诊断报告.md》给出的三个最确定根因——
1. ✅ **二面角 σ 不自洽**（`diffusion.py` 硬编码 0.03/1.55 vs yml 0.0314/3.14）→ 已改 0.0314/3.14（`959867a`）。
2. ✅ **二面角温度采样缺失**（`temp_sampling_tor=7.04` 定义未用）→ `reverse_step_torsion` 已补温度分支（`959867a`）。
3. ✅ **初始化不一致**（模板二面角 + 0–10 Å 壳 vs 原生均匀二面角 + 受体 COM 高斯）→ 已应用 patch `doc/假设3_初始化对齐.patch`（工作树）：`initialize_protac` 新增原生分支（均匀二面角 + 绕配体 COM 旋转 + 平移到受体 COM + N(0, tr_sigma_max²=19.0²)），`sampler.py` 改用 `e3_center = e3_coords.mean(0)` 作为初始化中心并传入 `tr_sigma_max=19.0`。

**验收结果 job 139693（2026-08-17，只含 #1+#2、不含 #3）**：零-FiLM 基线 E3-interface DockQ best = **0.0925**，**比 0.215 更差**（回归）；`protac_pocket_dist_mean` 52.5 Å、best 21.2 Å、`protac_rmsd_best` 5.56 Å（漂移未消除，反而变糟）。

**回归根因分析（关键）**：commit `959867a` 把二面角修复（#1/#2）与 **BUG-18 featurization 重表达**捆在了一起，导致这次 0.0925 **无法隔离**判断 #1/#2 的效果。更实质的是——BUG-18 修复后，featurized PROTAC 模板 COM 从「E3 原点（≈0，因旧 bug 各分子独立居中）」移到了「真实晶体位置（`lig_offset` = PROTAC 重原子质心 − E3 Cα 质心，见 `featurize_common.py:_true_relative_offsets`；注意这不是 `t_e3_to_poi` = POI−E3——`~20–40 Å` 那个量级属于 POI，PROTAC 的 `lig_offset` 是另一量级）」，暴露了 `sampler.py` 的一个旧 bug：`pocket_center = ligand_template.mean(0)` 用 **PROTAC 模板 COM** 而非 **E3 受体 COM** 作为初始化中心。于是 32 个 walker 从离 E3 口袋 20+ Å 处起步，去噪无法把 PROTAC 拉回口袋 → DockQ 0.0925、pocket_dist 21+ Å。这正是假设 #3 描述的初始化错位，现已随 patch #3 修复。

> 验收判据（达成才算闭环）：零-FiLM 基线 E3-interface DockQ **best of 32 ≈ 0.844**（原生 `0.844` 为 32 seed 取 max，非单 seed 值。初始姿态可逐 seed 对齐，但反向回路步数/调度不同，故以 best-of-32 统计口径对比，不设逐 seed 的 <0.02 硬对齐）。
> ⚠️ **待重跑**：patch #3 已应用但**尚未重跑验收**；且 patch #3 之前的基线（`959867a` 之前）在「近似正确」初始化下也只有 0.215，故 #3 之外可能仍有更深的循环问题（见 §2 候选排查点 1/2/4）。下一步 = 重跑零-FiLM 基线验收 job，若仍 <0.844 再逐项查 tr/rot/tor 反向步与原生 inference 的一致性。

## 3. 待决策（2 项）

### ① gate 无界

`MergeGateHead` 是裸 `Linear`，`g` 可 <0 或 >1（`s_q` 会越过 `s_q1` 或越过 `s_q2`）。文档方案 B 原建议 sigmoid+logit 初始化，但那从 `sigmoid(1)≈0.73` 起步、不是精确纯 E3-L。当前裸线性零初始化是**最干净透明性**（g 精确 =0），代价是无界。
- 选项：(a) 保留裸线性；(b) 加 `tanh`/clamp 到 [0,1]。
- **倾向**：先保留 (a)，观察训练里 g 的分布再定。

### ② POI-L 分支 FiLM head 梯度饥饿

`d(s_q)/d(s_q2) = g`，`g=0` 时 POI-L 子图 FiLM head 通过 PROTAC score 路径**拿不到梯度**；只有 `d(s_q)/d(g) = s_q2 - s_q1 ≠ 0`，所以 gate 自己先动，等 `g` 偏离 0 后 POI-L 才被「打开」。
- 选项：(a) 接受（gate 会自己动、POI-L 后置启动）；(b) 给 g 一个下限；(c) 给 POI-L 单独加辅助 score loss。
- **倾向**：先 (a)，观察训练日志里 gate 是否在动、POI-L 梯度是否起来。

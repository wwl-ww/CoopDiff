### D1 — 回归根因分析把 `t_e3_to_poi` 与 `lig_offset` 混为一谈

- **位置**：`doc/问题清单与修复状态 交接文档.md:97`。
- **原文**：「BUG-18 修复后，featurized PROTAC 模板 COM 从『E3 原点（≈0…）』移到了『真实晶体位置（本 case 的 `t_e3_to_poi` 分量尺度 ~20–40 Å 外）』」。
- **问题**：PROTAC 模板 COM 的重表达用的是 **`lig_offset`**（PROTAC 重原子质心 − E3 Cα 质心），不是 `t_e3_to_poi`（POI Cα 质心 − E3 Cα 质心）。见 `scripts/featurize_common.py:100-110`（`_true_relative_offsets` 明确返回 `(t_e3_to_poi, lig_offset)` 两个**不同**向量）与 `:300-306`（`poi_data['coords'] += t_e3_to_poi`；`ligand_data['coords'] += lig_offset`）。
- **后果**：文档用 `t_e3_to_poi` 的「~20–40 Å」量级来描述 PROTAC COM 的位移，但那个量级属于 E3→POI（POI 在远处）。PROTAC 靠近口袋，`lig_offset` 通常是**另一个（更小）量级**。这导致文档对「暴露 `pocket_center` bug 的位移」的归因张冠李戴——正确的向量名是 `lig_offset`，量级也应取 `|lig_offset|` 而非 `|t_e3_to_poi|`。
- **建议**：L97 改称 `lig_offset`，并把量级改成 `|lig_offset|` 的实际值（`featurize_common.py:307` 只打印了 `|t_e3_to_poi|`，未打印 `|lig_offset|`，建议同时补打印后者）。

## 2. 🟡 中优先级

### P1 — `initialize_poi` 仍绕原点旋转（patch 只修了 PROTAC，POI 同源 bug 未修）

- **位置**：`tricoopdiff/diffusion.py:738-739`。
- **代码**：`poi_pos = torch.bmm(poi_pos, rot) + translation.unsqueeze(1)`，其中 `rot` 施加于 `poi_template` 的**绝对坐标**，即绕**原点**旋转（非绕 POI 自身质心）。
- **问题**：这是 `initialize_protac` 假设 #3 的**同源 bug**。patch 已把 `initialize_protac` 改成「绕配体自身 COM 旋转」（`diffusion.py:697-699`：`torch.bmm(ligand_pos - ligand_center, rot.T)`），但 `initialize_poi` 仍是旧写法。BUG-18 修复后 `poi_template` 的质心在 `t_e3_to_poi`（~20–40 Å），绕原点旋转会额外平移 POI 质心（`t_e3_to_poi @ rot - t_e3_to_poi`），使「方向随机化」与「位置随机化」耦合，最终 POI 质心不再落在文档宣称的 30–60 Å 球壳内（而是 `translation + t_e3_to_poi @ rot`，量级可从 ~10 到 ~100 Å）。
- **影响**：`sampler.py:101` 用 `return_rotation=True` 取回的 `rot_init`（作为累积 SE3 旋转 `R_cum`）也因此与位置纠缠，不再是纯粹的取向。当前零-FiLM 基线里 SE3 头未训练、不影响 E3-interface DockQ（主指标），但会污染 POI DockQ 与 SE3 score-matching 训练。
- **建议**：`initialize_poi` 改成 `poi_center = poi_template.mean(0)` 后 `(poi_template - poi_center) @ rot.T + translation`（与 `initialize_protac` 原生分支一致）。

### D4 — 验收判据「同 seed <0.02」与「best of 32」语义不自洽

- **位置**：`doc/问题清单与修复状态 交接文档.md:99`（「零-FiLM 基线 E3-interface DockQ ≈ **0.844**（同 seed 下 <0.02）」），以及 `采样保真度诊断报告.md:5`（「0.215 vs 纯 DiffDock E3-L **0.844**」）。
- **问题一（量纲/语义）**：`0.844` 是原生 DiffDock 的 **best of 32**（32 个 seed 取最大），不是某个固定 seed 的单值。而判据「同 seed 下 <0.02」要求**逐 seed** 对齐——这是更严格、且与「best of 32」不同的比较口径。原生 0.844 对应的那个 best seed 是哪个、TriCoopDiff 是否在同一 seed 上比较，判据未定义。
- **问题二（可达性）**：即便初始化 RNG 已对齐（见下注），反向回路的步数/调度仍不同（假设 #4：原生 `actual_steps=19`、末步 t=0.10、`no_final_step_noise` vs TriCoopDiff 20 步、末步 t=0.05），且每步噪声消耗顺序不同，因此「同 seed 逐 bit 复现原生轨迹」在回路层面**不可能**达成，「同 seed <0.02」是一个不可达的硬指标。
- **注（对 init 的对齐澄清）**：`initialize_protac` 原生分支的 RNG 序列（`np.random.uniform` 二面角 → `scipy R.random()` 旋转 → `torch.randn` 平移）与 vendored `randomize_position`（`diffdock/sampling.py:34/44/57`）**同源同序**，故「初始姿态」在相同 `np.random.seed`+`torch.manual_seed` 下是可对齐的。patch 注释 `diffusion.py:641-642` 的「seed-comparable」仅对**初始姿态**成立，不覆盖整个反向回路。
- **建议**：判据改为「best-of-32 E3-interface DockQ ≈ 0.844（同 seed 序列，允许统计容差）」，或明确定义比较口径（同 best-seed 的 per-seed 值 vs best-of-32 值）。

## 3. 🟢 低优先级 / 潜在

### F2 — legacy `initialize_protac` 分支绕原点旋转（死代码，语义错误）

- **位置**：`tricoopdiff/diffusion.py:662-673`（`tr_sigma_max is None` 分支）。
- **代码**：`ligand_pos = torch.bmm(ligand_pos, rot) + translation.unsqueeze(1)` 绕**原点**旋转 `ligand_template`。BUG-18 修复后 `ligand_template` 在 `lig_offset ≠ 0`，绕原点旋转会连带平移 COM。
- **问题**：该分支仅在 `tr_sigma_max is None` 时命中；生产路径 `sampler.py:94-100` 恒传 `tr_sigma_max=diffusion.tr_sigma_max`，故**实际不可达**。仅剩的两个不带 `tr_sigma_max` 的调用方是 BUG-19 legacy 脚本（`scripts/inference.py`、`scripts/eval_entry.py`），它们 `sys.exit(2)` 提前退出、也不会走到。docstring 的「backward compatibility」理由已名存实亡。
- **建议**：删除 legacy 分支，或至少将其也改为绕 COM 旋转（与原生分支统一），避免后人误用。

### F3 — 原生分支对 `lig_mask_rotate` 缺 None 保护（潜在）

- **位置**：`tricoopdiff/diffusion.py:681-694`。
- **问题**：当 `lig_edge_mask is not None and bool(lig_edge_mask.any())` 成立、但 `lig_mask_rotate is None` 时，L684-685 会把它包成 `[None]*B`，L688 `mr = None` 传入 `modify_conformer_torsion_angles`（其内部 `mask_rotate[idx_edge, u]`）会抛错。
- **现状**：`featurize_common.extract_ligand` 已把 `mask_rotate` 归一化为单 `[n_rot, N_lig]` 数组，且 edge_mask 存在时 mask_rotate 也会存在，故生产路径不触发。属**潜在**防御性缺口。
- **建议**：在 L681 的 `if` 里同时要求 `lig_mask_rotate is not None`，否则跳过二面角随机化。

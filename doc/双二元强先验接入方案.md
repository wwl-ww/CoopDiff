# 双二元强先验接入方案

> 后续设计，尚未实现。当前唯一可运行初始化是 `sdpi`；本文的 sidecar、adapter、局部 proposal 和新 checkpoint 名称均不是现有 API。

## 目标与边界

本方案让 TriCoopDiff 在与 DeepTernary 可比的条件下使用两份独立二元界面先验，同时仍由模型求解三元装配。合法输入包括：PROTAC 两端原子身份、两端二元配体构象、由二元 pose 推导的两个蛋白口袋，以及两侧局部 keypoint/frame。禁止输入真实三元 E3–POI 变换、真实三元 ligand pose、三元 contact map 或用真实 DockQ 选择候选。

若未来实现，候选模式名为 `dual_binary_prior`，须单独版本化；当前无二元先验基线为 `sdpi`。旧 `coupled5a`、`anchor_local` 已删除。任何依赖测试三元相对 pose 的实验只能标为 oracle 诊断。

## 输入契约

每个样本使用版本化 `binary_prior` sidecar，而不是向 `forward()` 添加零散路径参数：

```text
input:  E3 protein, POI protein, canonical full PROTAC
prior:  E3-warhead binary pose, POI-warhead binary pose
        canonical atom maps, protein pocket residue IDs
        local keypoints/frames, confidence and provenance
target: ternary complex（只用于训练监督或最终指标）
```

Atom mask 使用 canonical heavy-atom 整数索引；蛋白口袋使用稳定的 `chain/resseq/icode` 标识。两份 binary pose 分别保存在对应蛋白的 body-local frame，不能假设原文件共享坐标系。缺失项用 `available`、`valid` 和 `quality` 显式表示，禁止用零坐标或 identity frame冒充有效先验。

缓存签名必须覆盖 sidecar、canonical ligand、两份 binary pose、atom/residue mapping、frame 生成器版本和全部来源文件 SHA256。新增先验后必须提升 featurization cache version。

## 模型如何使用先验

| 先验 | 表达 | 接收模块 |
|---|---|---|
| `lig1_mask/lig2_mask` | E3-warhead、linker、POI-warhead、attachment 的原子角色 embedding | TriFuse ligand encoder、逐原子 FiLM、torsion coordinator |
| 两端二元构象 | 参考内部距离、键角、手性、exit vector及映射置信度 | branch-specific prior encoder |
| protein pocket mask | residue flag、参考接触类型、距二元配体的距离编码 | TriFuse protein/interface encoder |
| keypoint/local frame | 当前状态相对二元模板的局部距离、方向不变量和 frame residual | TriFuse；后续可接小型等变 sidecar |

冻结 DiffDock base 保持原始节点维度、化学图和动态 cross-edge，不直接接收新字段，以保留 native parity。`sub1` 只接 E3 侧先验，`sub2` 只接 POI 侧先验；TriFuse 可以联合观察两侧不变量。原始 xyz 不能拼入普通 MLP，方向信息必须在局部 frame 中编码或由等变模块处理。

新增模块采用零初始化残差：当 `binary_prior.available=false` 或 prior adapter 输出为零时，新模型必须在默认容差内复现 `trifuse_v13` 的 tr/rot/tor 输出。

## 路线 A：从现有模型继续训练

这是已有可靠 `trifuse_v13` checkpoint 时的默认路线。

1. 将 version 17 权重完整加载到原模型；新增 `BinaryPriorEncoder`、prior token/edge adapter和 residual FiLM，全部零初始化。
2. 冻结 DiffDock base、两套 LoRA 和原 TriFuse，先只训练新增先验模块，确认四类输入都有有限且非零梯度。
3. 解冻 TriFuse，以低于 prior encoder 的学习率联合微调；保留现有 score matching 主损失。
4. 收敛后才启用两套独立 LoRA，LoRA 学习率建议为 prior encoder 的 `0.05–0.1`；两侧 adapter 不共享参数。
5. 保存为新 checkpoint 架构，例如 `trifuse_v14_binary_prior`，记录父 checkpoint 的绝对路径和 SHA256。不得覆盖或静默迁移 version 17 文件。

优点是保留现有双 expert 协调、torsion 和数值稳定能力，训练成本低。风险是旧模型可能形成无先验局部最优，因此必须与从头训练路线做同数据、同预算对照。

## 路线 B：从头开始训练

该路线用于验证旧 checkpoint 是否限制了强先验的利用能力。

1. DiffDock base仍从官方预训练权重加载并冻结；“从头”指 TriFuse、prior encoder、FiLM、bridge、torsion coordinator和两套 LoRA重新初始化，而不是随机初始化 DiffDock。
2. 首阶段只训练 prior encoder + TriFuse，LoRA保持关闭；先让网络学习双端点、双口袋和局部 frame 的条件语义。
3. 第二阶段启用两套 branch-specific LoRA，继续训练完整双界面 score matching。
4. 第三阶段加入结构化 prior dropout和 docking decoy，提高单侧/缺失/低质量先验下的鲁棒性。

只有在明确研究“DiffDock 预训练是否必要”时，才增加全随机 expert 实验；它不属于正式主路线。

## 训练目标与防止捷径

现有 E3–L、POI–L translation/rotation score matching和共享 torsion loss仍是主目标。可增加低权重局部辅助项：keypoint Kabsch-aligned RMSD、局部 frame residual、pocket-contact分类、warhead contact保持、linker strain和clash。二元 pose可能与三元状态存在 induced fit，辅助项不能成为硬坐标复制。

训练条件建议逐步过渡到：完整双先验 60%、仅 E3 15%、仅 POI 15%、无先验 10%。每侧使用独立 SE(3) gauge augmentation，并混入小扰动 pose、真实 docking候选和错误配对 decoy。跨 case 打乱先验后，模型置信度和质量应明显下降；轻微扰动不应导致采样崩溃。

## 推理与候选选择

E3固定。每对二元候选生成两类构造：`E3-exact` 保留 E3–PROTAC pose并通过 POI-warhead 对齐放置 POI；`POI-exact` 对称地保留 POI侧 pose。只允许调整 linker torsion，warhead核心作为约束。初态扰动必须调用与训练相同的 forward diffusion kernel并记录各自由度的 `t` 和 sigma。

公平评测建议40 walkers，两类各20，固定 walker-to-candidate和seed映射。Top-1只能使用预注册的二元置信度、closure/strain/clash以及经验证集训练的 ranking score；真实 DockQ只能在选择完成后计算。Oracle-best必须单独标为搜索上限。

## 验收与路线选择

实现前必须通过：target修改不改变任何 input/prior tensor；两侧 binary分别任意刚体变换后条件表示不变；整体刚体变换下模型输出保持等变；关闭 prior严格复现 v13；所有frame满足正交性和 `det(R)>0`；动态POI frame、crop和cross-edge始终同步重建。

按相同数据、步数、seed和计算量比较：现有无先验基线、现有模型继续训练、从头训练。主报 model-ranked Top-1 full-atom DockQ、两侧 interface DockQ/Fnat、valid率和clash；同时报告 oracle-best但不得混用。若继续训练达到同等或更好验证结果，优先采用路线A；只有路线B稳定显著领先时，才承担从头训练成本。

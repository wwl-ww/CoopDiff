## 一、参考系一致性专项

### 1.1 旋转约定逐行核对

**约定 1 —— `so3_exp(ω)` 返回标准 Rodrigues 矩阵 R**（`R·v` = v 绕 ω̂ 轴转 +θ，右手法则）。用 ω=θ·e_z 验证得 `R_z(θ)` ✅。

**约定 2 —— 代码统一用行向量 `X @ R`**。`X @ R = (R^T X^T)^T`，所以 `X @ R` = 每个点绕 **−ω** 转（即 `so3_exp(ω)` 作为 `X @ R` 用时，实际转的是逆方向）。

**结论：这条约定虽然是"反的"（`so3_exp(ω)` 当 `X @ R` 用 = 转 −ω），但它是全代码统一用的，所以只要前后一致就没问题。**

### 1.2 四处 frame 约定串起来核对

| 位置 | 代码 | 核对结果 |
|------|------|---------|
| `sampler.py:120` | `r_e3_to_poi = R_cum.transpose(-1,-2)` | `R_cum` 是累积到 POI 的旋转（`poi = template @ R_cum`），传 `R_cum^T` = POI 朝向的逆 ✅ |
| `train.py:118` | `r_e3_to_poi = se3_rot_noise.transpose(-1,-2)` | `se3_rot_noise` 是加到 POI 的噪声旋转（`poi_noisy = poi @ rot_update`），传 `rot_update^T` ✅（与 sampler 同一约定） |

| `model.py:201-203` frame fix | `scores_2 @ r_poi_to_e3`（`r_poi_to_e3 = R_cum`） | 把 POI 系 score 转回 E3 系 ✅ |

### 1.3 两个误报更正

- **BUG-6（rot_score 需 adjoint）——误报**。SO(3) **真旋转**（det=+1，无反射）下，so(3) 向量（轴向量/角速度类）与极向量（位置类）的变换**完全相同**，都是 `ω_e3 = ω_poi @ R`。反射（det=−1）才区分轴/极向量，而这里不涉及反射。所以 `rot_score @ r_poi_to_e3` 和 `tr_score @ r_poi_to_e3` 一样，都是对的。
- **BUG-7（train 的 r_e3_to_poi 约定）——误报**。`se3_rot_noise.transpose(-1,-2)` 与 sampler 的 `R_cum.transpose(-1,-2)` 是同一约定（都是"POI 实际朝向的逆"），一致。

### 1.4 真正的地基问题（已确证，比初判严重得多）

**初判（错误）**：`t_e3_to_poi = poi_center - e3_center` 差一个 `e3_center`。

**实测源码后修正（确证）**：读到 `DiffDock/utils/inference_utils.py:231-237`：

```python
protein_center = torch.mean(complex_graph['receptor'].pos, dim=0, keepdim=True)
complex_graph['receptor'].pos -= protein_center      # E3/POI → 自己质心 = 0
ligand_center = torch.mean(complex_graph['ligand'].pos, dim=0, keepdim=True)
complex_graph['ligand'].pos -= ligand_center         # PROTAC → 自己质心 = 0
```

`featurize_complex` 对 e3l/poil 各自用 `InferenceDataset`，结果是 **E3、POI、PROTAC 三个分子各自独立平移到原点**：

- `e3_center = 0`、`poi_center = 0`、`ligand_center = 0`
- 于是 `t_e3_to_poi = poi_center - e3_center = 0`（恒为 0）
- **E3↔POI、E3↔PROTAC、POI↔PROTAC 的相对平移全部丢失**（只剩各自朝向）

**训练后果（致命）**：score matching 的"干净"坐标是"三分子堆在原点"，模型被训练成"把配体/POI 去噪到原点"，而不是去噪到它们在三元复合物里相对 E3 的真实位姿。

**根因**：`InferenceDataset` 是 DiffDock 给**推理**用的（推理时配体平移是随机初始化的扩散变量，初始位置无所谓）。TriCoopDiff **训练**需要保留相对位姿作监督信号，却误用了推理数据集。正确做法是用 DiffDock **训练** featurization（`datasets/pdbbind.py` 那套，配体在受体坐标系里）。

## 二、数值/梯度专项

### 2.1 温度采样 + score 归一化（从 DiffDock 抄，假设正确）

- `reverse_step_protac` 的 `temp_sampling/psi/sigma_data` 三段式（`lambda_tr = (σ_data+σ)/(σ_data+σ/ts)`、噪声 `√(dt(1+ψ))`）是 DiffDock 的标准温度采样公式，逐行照抄，**假设正确**。
- `so3_score_norm`/`so3_score_vec`/`torus.score_norm` 都是预计算表查找，与 vendored DiffDock 对齐（`expert.py` 的 docstring 已声明 single source of truth）。

### 2.2 物理损失的梯度路径 —— 文档与代码不符

`train.py:8` docstring 写「`L_phys → x_denoised → s_tri_residual → TriBrain (direct path, not through FiLM)`」，但：

- 当前代码里**没有 `s_tri_residual`** 这个东西。
- 实际梯度走两条路：
  1. `loss_phys → x̂_ligand = _estimate_denoised(noisy_ligand, s_q['tr']) → s_q（= s_q1+s_q2，经 FiLM 调制）→ FiLM(γ,β) → TriBrain`（**经 FiLM**，与 docstring 说的相反）；
  2. `loss_phys → x̂_POI = _estimate_denoised_se3(noisy_poi, s_se3) → s_se3（SE3 head 直接）→ TriBrain`（直接）。

- 结论：docstring 是旧设计的残留，需要更新；梯度本身是通的（两条路都能回到 TriBrain）。

### 2.3 其余已确认正确

- Tweedie 去噪 `x̂ = x + σ²·score` 与 score target `-tr_noise/σ²`（其中 `tr_noise = σ·ε`，故 = `-ε/σ`）自洽 ✅
- `so3_exp` 的 Rodrigues 公式、`vector_to_skew`（`[v]×` 满足 `[v]× w = v×w`）✅
- `kabsch_align` 的 `R = U @ D @ Vt`（修过 transpose）✅
